## Key Code Changes

- `sync.py::BackgroundSyncCoordinator`: bounded `queue.Queue`, single daemon worker thread, `submit()`/`pause_barrier()`/`resume()`/`shutdown()`. Barrier uses a generation counter checked at callback delivery time — a job already dequeued and mid-network-call when `pause_barrier()` fires still runs to completion, but its callback is silently skipped, which is the mechanism that prevents a stale sync result from mutating SQLite state after a clear.
- `sync.py::sync_scan_batch_network_only`: mirrors `_sync_one_batch()`'s HTTP/retry/classification logic exactly but takes `scans`/`station_name` as parameters instead of querying `self.db`, returning `{synced_ids, failed_ids, pending_ids, synced_count, error}` for the caller to apply.
- `main.py::AutoSyncManager.trigger_auto_sync`: snapshot (main thread) → submit network-only closure (worker thread) → `QMetaObject.invokeMethod(..., QueuedConnection)` → apply DB mutations (main thread, in `_on_auto_sync_result`). Same shape reused in `Api.sync_now`/`_on_manual_sync_result`.
- Clear barrier applied to three sites: `_handle_clear_epoch_and_heartbeat_slot` (remote-clear detection), `admin_clear_cloud_data`, `admin_clear_station_data` — all three call `pause_barrier()` before `clear_all_scans()` and `resume()` after.

## Architecture Decisions

- Chose "main thread snapshots + applies, worker does network only" over "worker owns its own DatabaseManager connection" — the council round (my synthesis plus a corrected-by-Codex Slice B agreement) converged on this as safer and requiring no new SQLite connection-per-thread pattern.
- Kept `check_duplicate_cloud` (the synchronous cross-station dup check inside `register_scan`) explicitly out of scope for this slice — moving it async would require a two-phase scan-acceptance UX redesign that wasn't part of the agreed plan.
- One shared `BackgroundSyncCoordinator` instance across auto-sync, manual sync, and live-sync (rather than three separate coordinators) so jobs serialize instead of racing each other.

## Lessons Learned

- **Pattern**: When a message claims to summarize a tool's output, check the tool's actual output artifact (file, exit code) before building on the claim — a plausible-sounding summary is not evidence.
- **Discovery**: A factual claim repeated across multiple turns of the same conversation (by me or by the user) doesn't gain credibility from repetition — "SHA-256 idempotency" was wrong every time it was stated, including by me, until an independent read of the actual code caught it.
- **Pattern**: "Snapshot on main thread → network-only work on worker thread → apply on main thread via QueuedConnection" is a clean, repeatable shape for Qt+SQLite+background-thread problems — used it identically for auto-sync and manual-sync in this session.
- **Discovery**: A generation-counter-based barrier (bump generation, drop queue, skip stale callbacks) is a lightweight way to prevent stale async results from corrupting state after a synchronous invalidating operation (here: a data clear), without needing to block the calling thread waiting for in-flight work to finish.
- **Pattern**: When a codebase has multiple structurally-identical call sites for the same risky operation (here: three separate "clear scans" code paths), fixing one and not checking for siblings is a real gap — found the second and third clear sites needed the identical barrier only by deliberately grepping for `clear_all_scans()` after fixing the first.
