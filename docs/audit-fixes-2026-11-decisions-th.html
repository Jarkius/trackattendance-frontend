เรื่องที่ 1 · issue #109

ตัวเลข "อัตราการเข้าร่วม" สูงเกินจริง

ระบบคิดอัตราการเข้าร่วมจาก บัตรทุกใบที่สแกน ÷ จำนวนพนักงานที่ลงทะเบียน แต่บัตรทุกใบรวมบัตรที่ ไม่ใช่พนักงานในรายชื่อ ด้วย เช่น บัตรที่อ่านผิด บัตรแขก หรือเลขบัตรที่หายไปบางหลัก

พนักงานในรายชื่อ บัตรที่ไม่อยู่ในรายชื่อ
ระบบแสดงตอนนี้
120% 12 บัตร ÷ 10 คนที่ลงทะเบียน
ที่ถูกต้อง
100% 10 คน ÷ 10 คน · บัตรแปลก 2 ใบแยกแสดงต่างหาก

ตัวเลขผิดแสดงอยู่ 2 ที่

Dashboard บนเครื่อง kioskอยู่ใน repo นี้ (trackattendance-frontend)
Dashboard มือถือแบบสาธารณะ เพิ่งเจอหน้า /dashboard/ อยู่ใน repo trackattendance-api เจอตอน clone มาตรวจตามที่คุณแนะนำ
แนะนำ

ก. แก้ทั้ง kiosk และ API

  • ทั้งสองหน้าแสดงตัวเลขถูกต้อง
  • เพิ่ม field ใหม่ matched_unique ใน API ซึ่งนับเฉพาะพนักงานในรายชื่อ ของเดิมยังทำงานเหมือนเดิม
  • kiosk ใช้ field ใหม่ถ้ามี ถ้าไม่มีก็คำนวณเอง ไม่ต้องกังวลว่าจะ deploy อะไรก่อน
  • มีงานเพิ่มใน repo API อีกหนึ่ง branch

ข. แก้แค่ kiosk

  • งานน้อยกว่า ไม่ต้องแตะ API
  • หน้ามือถือสาธารณะ ยังแสดง 120% เหมือนเดิม

ถ้าเลือก ก. ผมจะทำบน branch แยกของ repo API และจะไม่ push หรือ deploy จนกว่าคุณจะอนุญาต

เรื่องที่ 2 · issue #112

เอกสารเขียนไม่ตรงกับการทำงานจริง

เรื่องนี้ ไม่ต้องแก้ API เพราะ API ทำงานถูกแล้ว แต่เอกสารล้าสมัย

docs/API.mdบอกรูปแบบข้อมูล export ผิด ระบุว่าเป็น array แต่ server จริงส่งเป็น object ที่มีข้อมูลมากกว่า
CLAUDE.mdบอกว่า export "แบ่งหน้า" แต่จริงๆ ส่งมาครั้งเดียว สูงสุด 100,000 รายการ

สิ่งที่จะทำคือแก้ข้อความให้ตรงกับความจริง และให้โปรแกรมเตือนใน log ถ้าข้อมูล export ถึง 100,000 รายการ ซึ่งแปลว่าอาจมีข้อมูลตกหล่น

ทำไมต้องถาม: กฎของโปรเจกต์กำหนดว่าการแก้ไฟล์ที่มีอยู่แล้วในโฟลเดอร์ docs/ ต้องได้รับอนุญาตก่อน
